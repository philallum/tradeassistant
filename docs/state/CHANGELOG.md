Outcomes H3 / H5 (hold 3 / 5 sessions from the open after the decision date) and BR (symmetric 1 x ATR14 bracket, at most 5 sessions, side touched first; ambiguous days count as losses), H1 as reference. Key design point: for each outcome the call is the majority of the analogues' OWN result for that outcome, with an analogue voting only if its outcome window had closed by the decision date (`j + span <= i`); judging the live next-day call on a 5-day move would have mismatched the question. - **Result (Evidence Report 3):** best directional uplift over weekly trend is V0/H3 +1.35pp (CI [-0.68, +3.38], q=0.73); every family-U and family-C cell has q >= 0.73; net per trade is negative in all 9 family cells (best V1/H3 -0.27, CI [-2.44, +2.11]). ROOT CAUSE (real engine bug, not a test artifact): in `src/strategies/confluenceEngine.ts` step 7, the ≥2-contributor classification was `if (score >= alignmentThreshold) ALIGNED_UP; else if (score <= -alignmentThreshold) ALIGNED_DOWN; else NEUTRAL`. When `alignmentThreshold = 0` and the net score is exactly `0`, the `score >= 0` branch claims the zero for ALIGNED_UP before the `score <= -0` branch can run. Because flipping UP<->DOWN leaves a zero score at zero (the engine normalises `-0`→`+0`), BOTH the original and the flipped set classify ALIGNED_UP — violating the symmetry invariant (Requirement 9.8). This is a latent contradiction in the spec itself: criteria 9.3 (`score >= alignmentThreshold`) and 9.4 (`score <= -alignmentThreshold`) both admit `score = 0` at `alignmentThreshold = 0`, while 9.8 demands symmetry. The minimal counterexample fast-check shrank to had `alignmentThreshold: 0` and subnormal strengths summing to exactly 0.

FIX (minimal, behaviour change only at the degenerate zero point):
- `src/strategies/confluenceEngine.ts` — added `if (score === 0) status = "NEUTRAL";` as the FIRST arm of the ≥2-contributor branch, so a score of exactly 0 (no directional lean) is always NEUTRAL regardless of threshold. Every NON-zero score follows 9.3/9.4 exactly as before. Comment cites Req 9.5/9.8.
